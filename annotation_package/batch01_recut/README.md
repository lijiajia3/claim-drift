# batch01 重标包 · 使用说明

> 目的:修复首轮标注失败(工具停在旧三维度方案 + 标注者 2.4 秒/句划默认值),
> 用带**防呆 + 质控闸**的新流程重标一批,产出投稿需要的 κ / α / ρ 三个数。
> 首轮 zenan wu 的数据已作废,不要复用。

## 1. 这个包里有什么

| 文件 | 给谁 | 用途 |
|---|---|---|
| `batch01_import.csv` | **上传 Label Studio** | 368 个任务,只有 `task_id`+`sentence`,绝对盲 |
| `batch01_KEY_PI_ONLY.csv` | **只留 PI(你)手里** | 金标答案 + 盲重复映射 + model_s,**严禁发学生** |

**批次构成**:330 普通句 + 26 硬金标(8 hedged / 10 definitive / 8 non-assert,全部经逐条人工审定,剔除歧义句)+ 12 盲重复,共 368。
盲重复与其原句在序列里间隔 ≥176,学生看不出是同一句。

## 2. 部署前:PI 必做的一步(不可跳)

金标已经过一轮逐条审定(剔除了引用方自述/假设、撞手册降档规则的句子),但**你仍需自己复核确认**(尤其 8 条 non-assert,它们最 tricky)。
打开 `batch01_KEY_PI_ONLY.csv`,只看 `item_type` 为 `gold_*` 的 26 行(已经过一轮逐条审定,你复核一遍即可):

- `gold_hedged` → 该句确实只用 may/might/could 等试探语气转述结论 → 正确答案:转述=1, 确定性≤0.25(区间判,邻档不算错)
- `gold_definitive` → 该句确实用 causes/proves/well established 等断定语气 → 转述=1, 确定性≥0.75(区间判)
- `gold_nonassert` → 该句确实只在讲方法/范式/设计,没转述任何结论 → 转述=0

任何一条你觉得有歧义 → 从 KEY 里删掉那行的金标身份(改 item_type 为 `ordinary`),别让一条可疑金标去误伤标注者。

## 3. 操作流程

1. **建项目**:Label Studio 新建项目 → Labeling Interface 粘贴 `label_studio_config_v2.1.xml` 全文。
   - 检查:两问都是 `required`、没有任何选项被默认勾选(不选无法提交)。这一条直接杀死"划默认值"。
2. **导入**:上传 `batch01_import.csv`。**确认项目里没有 model_s / 任何答案列**——盲标是命根子。
3. **发说明**:把 `../标注说明.md` 发给 **≥2 人、最好 3 人**,独立标同一批,不许讨论、不查原文、不用 AI。
   - 当面强调:这是**读句子做判断**的任务,不是点选;2 秒一句一定会被判作废重标。
4. **收卷**:每人导出 CSV(File → Export → CSV),确保含 `task_id, assert, certainty, lead_time` 列。
5. **打分**:
   ```bash
   cd annotation_package
   python3 score_batch01.py 学生A.csv 学生B.csv 学生C.csv
   ```

## 4. 三道质控闸(每人先过,才有资格进 IAA)

| 闸 | 指标 | 通过线 | 拦的是什么 |
|---|---|---|---|
| 1 耗时 | 中位 lead_time / <5s 占比 | 中位 ≥8s **且** <5s 占比 <30% | 划默认值(zenan 中位 2.4s → 秒毙) |
| 2 金标 | 26 条硬金标答对率(区间判) | ≥80% | 没读句子 / 乱标 |
| 3 盲重复 | 12 对自我一致率 | ≥75%(转述一致 + 确定性差 ≤1 档) | 随机作答 |

任一闸不过 → 该人数据作废,当面重新交代后重标。**注意**:划水者常在闸 3"自我一致"上蒙混(总填同一个值),
所以闸 1、闸 2 才是主锁,不能只看一致性。

---

## 5. 最终闸门(≥2 人过闸后自动算)

脚本汇总输出三个数,全部 ≥0.60 才算通过:

- **断言 κ**(Fleiss/Cohen):人判"是否转述"彼此一致度
- **确定性 Krippendorff α**(序数):人判五档确定性彼此一致度
- **人-模型 Spearman ρ**:人评均值 vs LLM 的 model_s —— 这就是验证打分器的核心数

三个数达标 → 填入 `manuscript/main.tex` 里那几处 `[TODO: κ, α, ρ]` → 投稿闸门开。
若某个数 <0.60 → 按预注册规则做评分者诊断、修订 codebook、重标,**不许事后放宽门槛**(THEORY.md:不 rig)。

---

## 6. 为什么不用"AI 标 6000 + 人工审核"抄近路

已否决:①破坏独立性——用人确认 AI 的分 = 用 AI 验证 AI,审稿人必拒;
②对会划水的标注者,给他看 AI 答案会因锚定造出**虚高假 κ**,是学术不端灰区。
盲标这 368 条做干净,就足够验证打分器,**不需要标 6000 条**。
